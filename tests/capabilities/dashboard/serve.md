Команда `dashboard` сама сервит страницу на `127.0.0.1` и открывает её в браузере; страница рисуется на сервере.

SVG собирается строкой в скрипте — геометрию проверяет `bun test`, без браузера, зависимостей и CDN. В браузере
остаётся только подсказка при наведении; всё, что она показывает, есть и в таблице под графиком.

Сервер слушает только `127.0.0.1` и отвечает только на своё имя: страница называет задачи непубличных
репозиториев, а сайт, навёдший своё имя на `127.0.0.1` (DNS rebinding), читал бы её из браузера пользователя.

Отказ `listen` Bun отдаёт как `EADDRINUSE` на любом порте — и когда порт занят, и когда слушать запрещено (песочница
агента). «Порт занят» скрипт пишет, только если свободный порт взять можно, иначе — что локальный порт здесь не
открыть: на «port 0 is busy» агент перебирал порты, вместо того чтобы запустить сервер вне песочницы.

Отвергнуто: подкоманда `est dashboard` — графиков станет больше, а `est.ts` уже велик; файл HTML без сервера —
данные устаревают в момент записи, а страница с сервером перечитывает проект при открытии.

Где запускать дашборд, замерено на macOS (#396): без `sandbox.network.allowLocalBinding` песочница Claude Code не
даёт слушать порт; с ней сервер слушает и читает маршруты прокси, но `gh`, которого скрипт запускает, в песочнице
не проходит проверку TLS (`x509: OSStatus -26276`), и вкладка остаётся без задач — запись `gh *` в
`excludedCommands` выводит из песочницы прямой вызов, а не дочерний процесс скрипта. Поэтому дашборд запускается вне
песочницы, а `allowLocalBinding` нужна его тестам, которые поднимают свои серверы с подставным `gh`, — медленному
уровню `test:slow` (`tests/standards/tests/fast-tests`).
