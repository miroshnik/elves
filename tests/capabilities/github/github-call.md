Ошибка вызова команды скилла `github` — две строки: что не так и исправленная команда целиком, `bun --no-env-file
<скрипт> …` с остальными аргументами вызова, а не «см. `--help`» (#841). Агент вставляет её как есть.

Справку читали заранее, а не после ошибки. За 1–16 ноября (1 282 сессии, 7 250 вызовов `github.ts`) `--help` — 628
вызовов, 9 %: `task edit` — 181 на 556, `task status` — 14 на 54, `task new` — 136 на 573, `task finish` — 38 на 332,
`task answer` — 10 на 109, у остальных меньше 5 %. 124 из 136 `task new --help` и 171 из 181 `task edit --help` — до
первого вызова команды в сессии, после её же ошибки — 0 и 2: синтаксис не угадывается (`SKILL.md` давал `task edit`
строкой `--replace|--add|--check … # --help`), а ошибка отправляла читать справку — ход на полном контексте. Отсюда два
хода: синтаксис целиком в `SKILL.md` и безопасный вызов — его ошибка и есть работающая команда.

Частые промахи — по ошибкам вызовов с 15 сентября по 16 ноября (2 425 сессий, 21,4 тыс. вызовов):

- `task new` (1 881 вызов, 43 ошибки): `--branch-type` — 404 из 437 вызовов ноября; с #835 его нет, и каждый такой
  вызов падал бы на неизвестной опции — теперь команда без него; `--priority` в личном аккаунте — 17 (с #682 — строка
  ○); `--labels` с разделом вместо темы — 4 (ошибка называет метку темы); закрытый эпик — 3; `--type` на другом языке — 2.
  Без `--title` и с заголовком аргументом — ошибка с командой, где он значение `--title`, иначе `<title>`.
- `task edit` (842 вызова, 77 ошибок, около 25 из них — отказы изоляции worktree составным командам, не скрипта):
  `--add` в раздел, которого в описании нет, — 27, почти все — «## Сценарии» и «## Вопросы»; `--add` с именем без
  «##» («Вопросы») — 18; `--check` без неотмеченного пункта — 3; `--replace` не найден или дважды — 2; лишний аргумент —
  1. Формы `--replace` (194 вызова в ноябре), `--add` (149) и `--check` (96) зовут все — ни одну не убрали; частая
  правка — вопрос или сценарий в раздел — одной очевидной формой: раздел по имени без «##», а недостающий раздел канона
  (вопросы, сценарии) `--add` создаёт в конце описания. Другой недостающий раздел — отказ со списком разделов описания:
  опечатка в имени не заводит лишний раздел.
- `task answer` (349 вызовов, 15 ошибок): нет нумерованного раздела вопросов — 9; вопрос уже с ✅ — 5; текст ответа с
  `--` — 1: `parseArgs` принимал его за опцию — теперь команда с текстом после `--`.
- `task status` (951) и `task finish` (683) промахов вызова нет: их ненулевые коды — остановки флоу (красный CI, шаг
  мержа), справку читали ради кодов и синтаксиса — его теперь даёт `SKILL.md`.

Исправления: опция, которой у команды нет, — та, что имелась в виду (`--parent` → `--epic`, `--label` → `--labels`,
опечатка до двух букв); ушедшая (`--branch-type`) — без неё и её значения; текст с дефиса — после `--`; опция без
значения — `<имя>` на его месте; значение с дефиса — склеено через `=`; флаг со значением — без него; `task edit` без
номера — `<N>` первым. Исправления нет — строка называет опции команды, следом её синтаксис. Список опций — синтаксис
справки команды: одно место для справки и для исправления.

Отвергнуто: печатать справку при ошибке — длинный абзац, который вызов не исправляет; выполнять исправленный вызов
самому — угаданная по опечатке опция завела бы задачу или переписала бы описание не так, а агент видит команду и
зовёт её одним ходом; проверять опции каждой команды отдельно (`task new --resume` разбор `task` принимает и
игнорирует) — промахов этого вида в вызовах нет.
