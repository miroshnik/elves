Добавленный PR-ом тест должен падать на базовом коде: «проверка пишется до кода и сначала красная» — главное обещание
флоу, и держалось оно на слове агента. `spec-break` запускали 22 раза на ~500 влитых PR (1–16 ноября), а при переносе
старой спеки в одном проекте нашлось не меньше 165 тестов, которые числились покрытием и не ловили поломку. `spec-red`
делает обещание механизмом: `github pr premerge` гоняет добавленные PR-ом тесты на коде базы с тестами PR — один раз на
PR и на любом пути к мержу, в пачке тоже, где CI на PR нет.

Добавленные тесты — статически, как в теле PR (`spec-diff`): переименованный и перенесённый тест — не новое требование,
а тесты харнесса по элементам не проверяются — у инварианта есть свой нарушитель. Тест, чей файл на базе не
загрузился, — красный: он импортирует то, что добавляет PR.

Тест существующего поведения — перенос спеки, тест «из кода» по следу решения — был бы зелёным и до PR. Для него
отметка в файле теста перед его `it` или `describe`, с номером задачи и причиной, как у исключений:
`// spec-existing #N: причина`. Отметка — запись о самом тесте, поэтому в его файле, а не в общем списке: тест удалён —
отметка уходит с ним. Храповик: отметка у теста, красного на базе, — ошибка, она не нужна.

PR в пачку проверяется против пачки, а её выпуск — против main (#892). Тест поведения, которое в пачку принесла другая
её задача, против пачки зелёный, на коде main — красный: с отметкой выпуск краснел по храповику, без неё не вливался PR —
каждая такая отметка всплывала только на выпуске, и круг «выпуск → починка → полный прогон» шёл заново. Поэтому для PR в
пачку `pr premerge` даёт spec-red вторую базу — main (`--also`): добавленные тесты, зелёные против пачки, идут и на коде
main. Красный там без отметки — проходит: тест проверяет изменение пачки, и «красный первым» выпуска держится; с
отметкой — ошибка «против main отметка не нужна». Отметка на PR в пачку значит «поведение есть в main» — ровно то, что
проверит выпуск. Цена — второй прогон только зелёных против пачки тестов этого PR; «красный первым» на PR в пачку
слабее: тест задачи Б на изменение задачи А той же пачки проходит без отметки — его держит выпуск.

Отвергнуто:

- Гонять в `precommit` — он идёт на каждый коммит, а красный на базе — свойство PR целиком; в CI отдельным джобом — PR в
  пачку CI не запускает, проверка прошла бы мимо половины PR.
- Гонять тесты на голой базе, без тестов PR: добавленного теста там нет, проверять нечего. Код — базы, тесты и их
  хелперы — PR.
- Гонять файлы добавленных тестов целиком: старые тесты того же файла шли бы зря, а у bun test есть фильтр по полным
  именам.
- e2e на базе: приложение для них идёт из стека задачи, а не из кода базы — строка ○, без проверки.
- Раннеры Vitest и Jest: тесты проекта — bun test и Playwright (эпик #906), файл другого раннера или проект не на Bun —
  строка ○, без проверки.
- PR в пачку против main целиком, базы выпуска: на каждом PR шли бы добавленные всей пачкой тесты — прогон рос бы с
  пачкой. На выпуске отметку у теста, красного на коде main, — строкой ○: храповик отметок на выпуске выключен. Ничего
  не делать — каждая неверная против main отметка всплывает на выпуске и чинится в пачке (#884) (#892, вопрос 1).
