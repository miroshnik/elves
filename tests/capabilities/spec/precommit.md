Скрипт `precommit` скилла `spec`: проверки перед коммитом — одним вызовом, со строкой на проверку и подробностями
только упавших.

Набор проверок перед коммитом — `lint`, `typecheck`, `test:spec` и затронутые правкой тесты (`docs/testing.md`, «Run
and result») — агент гонял отдельными вызовами, а на каждом круге исправлений — снова все. Длинный вывод раннера уходил
в контекст целиком: ≈ 15 ходов на задачу в пяти проектах (#671, эпик #663). Ход дорог не сам по себе, а тем, что каждый
перечитывает растущий контекст.

Решение:

- одна команда — `elves precommit` пакета (`bun --no-env-file node_modules/.bin/elves precommit`), в Elves —
  `bun run precommit`; скрипты проекта идут менеджером пакетов проекта (`projectCommands` скилла `github` — стандарт
  `package-manager`), от корня git;
- все проверки стартуют разом: каждый скрипт уже обёрнут в очередь машины (скилл `slot`), и сколько их идёт вместе,
  решает очередь, а не команда; своей очереди у команды нет — её слот держал бы вложенные скрипты мимо очереди;
- `test` получает `--changed=<base>`: база по умолчанию — `origin/main`, в пачке — `--base origin/<ветка пачки>`;
  у npm аргумент идёт после `--`, у остальных — как есть;
- скрипта нет в `package.json` — строка `○`, не провал: у проекта может не быть линтера;
- строка на проверку — по мере окончания: `✅`/`❌`, что решило, время; в конце — подробности только упавших: их вывод
  без строк прошедших тестов и эха команды менеджера, последние 80 строк, и файл со всем выводом;
- результат тестовой проверки — по сводке раннера (`bun test`, Vitest, Jest, Playwright), а не по коду выхода
  (`docs/testing.md`): нет сводки — прогон не дошёл до конца, каков бы ни был код; упавшие тесты при коде 0 — провал;
  зелёная сводка при коде не 0 — тоже провал: ошибка вне тестов; у `lint` и `typecheck` сводки нет — решает код;
- коды: 0 — всё зелёное, 1 — проверка упала, 2 — ошибка вызова (аргументы, нет `package.json`).

Отвергнуто: скрипт `precommit` в `package.json` проекта, который ставит установка, — ещё одна строка, которую `check`
сверял бы с релизом, а команда пакета уже идёт версией проекта. Место — скилл `spec`: проверки перед коммитом — ворота
спеки (`checks.md`), а `slot` других скиллов не импортирует (стандарт `scripts#skill-imports`), менеджер пакетов же отвечает
только `github`.
