Облачная сессия Claude Code (claude.ai/code, `CLAUDE_CODE_REMOTE=true`) — вне флоу: установщик и скрипты скиллов
`github` и `est` в ней отказывают одной строкой и кодом 2, а не работают вполсилы. Задачу ведут в локальной сессии.

Решение владельца (#837, эпик #833): за всё время — два импорта облачных сессий в факт, а поддержка облака стоила
справочника на 2 тыс. слов (`docs/cloud-sessions.md`), своего хука `SessionStart` в `.claude/settings.json` каждого
проекта, строки окружения в `check` и обходных путей в скиллах. Проекта GitHub облаку не видно (403), ветку назначает
оно само, транскрипт — не на машине, хука машины там нет: половина флоу не работала, и скрипт, который шёл дальше без
неё, давал непонятный сбой `gh` или неполный факт. Один отказ с причиной дешевле и честнее: агент сразу видит, что
работа — для локальной сессии. Вернуть облако — по запросу владельца, отдельной задачей.

Облако узнаётся по переменной `CLAUDE_CODE_REMOTE`, которую Claude Code ставит своим облачным сессиям и setup script
их окружения, — ровно `true`, иначе скрипт работает как обычно. Отказ — первым делом в точке входа, до справки и
разбора команды, у любой команды; строка и код одни у всех трёх скриптов. Хук облачной сессии, который прошлая версия
клала проекту (#610), `install` и `update` убирают (capability `elves#update`). Отвергнуто: отказ только у команд,
которые ходят в GitHub Projects, — так было (стандарт `scripts#cloud-session`), и остальное в облаке работало
вполсилы, а флоу держал ради этого хук, справочник и ветки кода в трёх скриптах.
