Менеджер пакетов проекта — Bun (эпик #906): скрипты флоу запускают команды проекта через `bun` и `bunx`, веток npm,
pnpm и Yarn у них нет (#910). Остался один вопрос — на Bun ли проект, — и на него отвечает одна функция:
`packageManager(dir)` скилла `github` по одной таблице случаев, а `pr premerge`, `spec-red` и строки стека проекта у
`check` берут ответ у неё.

Ответ нужен трём местам. `pr premerge` ставит зависимости слияния `bun install --frozen-lockfile` по lockfile Bun и зовёт
скрипты `bun run` (`projectCommands`); `spec-red` гоняет файл теста без импорта раннера через `bun test` только в
проекте на Bun; `check` называет строкой `❌` поле `packageManager` и lockfile другого менеджера — проект не на Bun,
`install` в него отказывает (#907). До #910 ответ различал npm, pnpm, Yarn 1 и Yarn 2+: `premerge` звал `pnpm run`,
`npm ci` и `npm run … -- <файлы>`, обёртка slot на Yarn 2+ была строкой у slot пакета через bunx, а копии правила
расходились — забытый `bun.lock` при `packageManager: "pnpm@…"` давал `premerge` pnpm, а `check` — `bun test`; забытый
`.yarnrc.yml` переключал обёртку на shell Yarn при любом менеджере. Ветки держали проекты, которых у флоу нет, — и
ошибались в чужом проекте поздно. Копии здесь не нужны, в отличие от стандартов-копий (`task-branch`): ответ нужен самому
`github`, скиллу `spec` и установщику `bin/elves.ts`, а установщик — не скилл и уже импортирует `github.ts` (граф
импортов скиллов — стандарт `scripts#skill-imports`).

## Правило

- на Bun — нет ни поля `packageManager` другого менеджера, ни его lockfile; поле `bun@…` или его отсутствие — Bun:
  `bun init` поле не пишет;
- не Bun — поле другого менеджера как написано (`pnpm@10.1.0`, `yarn@4.9.1`) и lockfile других менеджеров по порядку:
  `pnpm-lock.yaml`, `yarn.lock`, `npm-shrinkwrap.json`, `package-lock.json` — по ним `check` называет проект не на Bun;
- lockfile для установки — свой у Bun: `bun.lock`, иначе `bun.lockb`; ни одного — без установки;
- `.yarnrc.yml` ничего не решает: Yarn 2+ — не Bun по полю или по `yarn.lock`, своей ветки у него нет.

Реестр ответов — скрипты скиллов, которые экспортируют `packageManager`; каждый сверяется с таблицей. Второй реестр —
скрипты флоу со словами npm, pnpm, Yarn или npx: в их коде нет строки, которая начинает команду этих менеджеров (имя для
spawn, элемент argv, начало команды), — «пакет из npm» в справке и переменная `npm_lifecycle_script` (её ставит и
`bun run`) не команды. Скрипт флоу (`skills`, `bin`) не читает поле `packageManager` из `package.json` и не называет
lockfile или `.yarnrc.yml` строкой мимо этой функции: их место — тело `packageManager` в `github.ts`. Список lockfile в
`est.ts` (`DIFF_EXCLUDE`) — файлы вне счёта диффа, а не менеджер пакетов: PR, который переводит проект на Bun, удаляет
`package-lock.json`, и его тысячи строк — не работа; это регулярка путей, правило её не касается.
