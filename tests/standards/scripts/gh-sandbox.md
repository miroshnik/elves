Скрипт флоу на `gh` в песочнице Bash Claude Code не печатает ошибку `gh`: песочница закрывает проверку сертификата, и
каждый вызов падает на TLS (`x509: OSStatus -26276`). Скрипт печатает одну строку — gh не работает в песочнице, и
команда целиком, этот же вызов, для запуска вне неё (`dangerouslyDisableSandbox`) — и выходит со своим кодом отказа:
`github`, `est`, `spec-run`, `elves` — 2, `wait-ci` — 3 (строка — `RESULT: ERROR …`). Строка и её образец — одни на
флоу: `skills/github/scripts/command.ts`, у `wait-ci.sh` — копия, одинаковость держит этот тест.

Почему (#868): скрипт печатал ошибку `gh`, и агент тратил ход на догадку, а правило «сразу отдельным вызовом вне
песочницы» держала только строка канона (`claude/CLAUDE.md`, «gh fails in the sandbox») — исключением стандарта
`documents#canon-rules`. Теперь правило держит строка скрипта: агент запускает напечатанную команду как есть.
Отказ — не ошибка запроса скрипта (`GhError`, `EstError`): ни один перехват ошибок запроса его не глотает, и сеть его
не повторяет — в песочнице повтор упал бы так же.

Реестр — скрипты флоу со строкой `#!`, которые зовут `gh` процессом: новый скрипт на `gh` без пробы в тесте — красный.
Вне охвата — `task-env`: в песочнице он останавливается раньше, на Docker, своей строкой о запуске вне песочницы.

Отвергнуто: строка «gh не работает в песочнице» без команды — агент собирал бы вызов заново; повтор вызова вне песочницы
самим скриптом — выйти из песочницы скрипт не может.
