Закрепление задачи за сессией — файл `sessions/<id сессии>` в каталоге личной конфигурации (стандарт `scripts#config-dir`) со
строкой `owner/repo#N` — каждый скилл разбирает одинаково: на вопрос «за какой задачей эта сессия?» `github` и `est`
отвечают одно и то же.

Пишет закрепление `github task status`, читают двое: `github` — держит сессию за одной задачей и называет ожидание для
перезапуска в `task resume` (хук `SessionStart`), `est` — отдаёт закреплённую сессию задаче в факте целиком. Общего
модуля нет: `github` других скиллов не импортирует (стандарт `skill-imports`). Копии разбора расходились на краях:
строку не по форме `est` пропускал, `task resume` падал с кодом 2. Другая запись в `task status` — и `est` молча терял
бы привязку сессий в факте, хук — ожидание для перезапуска.

## Правило

- `owner/repo#N` — задача: репозиторий `owner/repo` как записан (регистр, точка, дефис, подчёркивание), `N` — номер
  целиком; пробелы и перевод строки по краям файла не в счёт;
- всё другое — не закрепление: пустой файл, номер без репозитория, лишний сегмент пути, хвост за номером, пробел
  внутри, вторая строка, ссылка на задачу. Сессия с таким файлом свободна для обоих: `est` её не привязывает,
  `task resume` пишет строку ○ с путём файла (код 0), `task status` перезаписывает файл задачей.

Разбор — функция `sessionPin(text)` в скрипте скилла: `{ slug, number }` или `null`. Реестр — скрипты скиллов, которые
её экспортируют; каждый отвечает по одной таблице. Строку пишет `pinLine(slug, number)` в `github` — каждая копия
читает её как ту же задачу. Скрипт, который читает каталог `sessions/` (сегмент под каталогом конфигурации или
`PINS_DIR` `est`), разбирает строку через `sessionPin`.
