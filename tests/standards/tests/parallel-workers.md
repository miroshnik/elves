Тесты Elves идут в воркерах `bun test --parallel`: скрипты `test`, `test:slow`, `test:spec` и `spec:doc` берут число
воркеров из `ELVES_SLOT_CPUS`, без него — по ядрам; дочерний процесс прогона не видит `JEST_WORKER_ID` воркера.

Одним процессом прогон шёл файл за файлом: в CI шаг `spec:doc` занимал 5:40 из ~6 минут (338 с, 3 014 тестов в 73
файлах). Тесты Elves в основном ждут дочерние процессы, а не считают: замер 2026-11-26, быстрый уровень в слоте машины,
bun 1.4.5 — последовательно 278 с, в 4 воркерах 93 с, процессорное время почти то же (233 с против 247 с) (#904).

## Число воркеров

`--parallel${ELVES_SLOT_CPUS:+=$ELVES_SLOT_CPUS}`: в слоте машины — его доля ядер (скилл `slot`), без переменной —
голый `--parallel`, по ядрам. CI идёт без очереди (`slot` там не ставит переменную), и `spec:doc` берёт ядра раннера.

## Файл времён в CI

С `--timings` воркеры первыми берут самые медленные файлы: файл стеков `task-env` на настоящем Docker идёт ~90 с, тесты
одного файла — подряд, и, стартуй он последним, прогон ждал бы его один. `spec:doc` читает и обновляет
`.test-timings.json` (`--update-timings`); прогон main сохраняет его в кэш Actions под ключом с `run_id`, PR и main
восстанавливают последний по префиксу ключа — без коммитов и без права `actions: read`. Нет файла — порядок не по
длительности, прогон не краснеет.

## JEST_WORKER_ID

Воркер `--parallel` ставит `JEST_WORKER_ID` и `BUN_TEST_WORKER_ID`, дочерние процессы наследуют окружение, и
`playwright test` под ним отказывается идти: «Playwright Test needs to be invoked via 'npx playwright test'» — краснели
тесты фильтров шарда Playwright в `tests/capabilities/spec/spec-shard`. Preload прогона (`bunfig.toml`) убирает
`JEST_WORKER_ID` из окружения, как `spawn-no-jit` ставит `BUN_JSC_useJIT`; `BUN_TEST_WORKER_ID` — свой у bun, его
никто не принимает за Jest, и он остаётся. Дочерние процессы `node:child_process` берут `process.env` прогона;
`Bun.spawn` без `env` берёт окружение, с которым процесс стартовал, — ему `env` передаётся явно.
