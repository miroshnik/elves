README — витрина флоу для того, кто видит репозиторий впервые, и он не отстаёт от флоу: называет каждый скилл, каждую
команду установщика и скиллов с её подкомандами, каждый справочник `docs/`, а его ссылки и якоря ведут на существующее.

README читают первым, а правят последним: новый скилл или справочник появлялся в `skills/` и `docs/`, а README о нём
молчал (так было со `spec-break` и `parallel-checkouts.md`; пока подкоманды не сверялись — с `github task close`).
Поэтому то, что можно перечислить из кода, README обязан назвать — иначе красный `bun test`.
Проза (мотивация, принципы, сравнение с OpenSpec) детерминированно не проверяется, но принципы ссылаются на разделы
`AGENTS.md`: переименовал раздел — проверка ссылок покажет README, и его абзац сверяется заодно. Поменял смысл раздела,
на который ссылается принцип, — поправь и принцип.

Витрина открывается именем флоу: заголовок **Elves**, под ним слоган **Elves at work** (табличка «Men at work»), ниже —
строка, что это за флоу.

Строка под слоганом и раздел «What it is» называют стек флоу — Claude Code, Bun и GitHub — с исключениями Playwright
для e2e и Next.js, пока его сервер идёт под Node, и проверкой `elves check`, которая его держит (эпик #906, #911): Эльфы
под ним написаны, проверены и запускаются, универсальности нет. До #911 README называл только агента, а Bun и GitHub —
нигде как требование: проект не на Bun узнавал об этом от `check`, а не из витрины. В каноне стек — правило «Elves is
for Claude Code, Bun and GitHub» с механизмом `elves check` (`canon-rules`); другому агенту — `docs/other-agents.md`.
